# cache-resume Specification

## Purpose

Результат единицы работы привязан к хэшу её входа; падение/рестарт/STOP
доезжают с места остановки за стоимость остатка; смена промпта инвалидирует
ровно конус зависимостей. Закрывает аудит §2. Этап 2 контракта (исполняется
3-м, ПОСЛЕ [[llm-contracts]]: «вход» для хэша определяется контрактом).

As-is (карта §1-3, §6, §8): состояние = один enum `Project.status`; рестарт
процесса откатывает статус (`startup_guard.py:70-187`); кэш по входу — только
ASR; чекпоинты img_pr/scene_design короткозамыкают по имени/uuid БЕЗ проверки
входа; INFLIGHT-маркеры без TTL/owner (`img_streams.py:20-21`); в репо 4
реконсайлера + 10 recover_*-функций — система регулярно реконструирует
состояние по диску.

## Requirements

### Requirement: input_hash на единицу работы

Каждая единица LLM/медиа-работы (NodeRun, батч, кадр-генерация) SHALL хранить
`input_hash = hash(нормализованный вход + версия промпта + модель +
параметры генерации)`. Место хранения: `NodeRun.meta` / `Frame.attrs`
(существующие JSON-колонки, без новых таблиц).

#### Scenario: Повтор с тем же входом
- **WHEN** шаг перезапущен, input_hash единицы работы совпадает с сохранённым
  при успешном результате
- **THEN** результат переиспользуется без LLM/медиа-вызова; в логе — cache hit

#### Scenario: Вход изменился
- **WHEN** мастер-промпт/модель/вход изменены (hash не совпал)
- **THEN** чекпоинт единицы инвалидируется, работа выполняется заново;
  «протухший» результат не подтягивается (as-is подтягивается: чекпоинты
  img_pr/scene_design по имени, аудит §2)

### Requirement: Инвалидация ровно конуса зависимостей

Смена входа узла SHALL инвалидировать его результат и результаты только
зависимых от него узлов (вниз по конвейеру), не трогая независимые.

#### Scenario: Смена промпта img_pr
- **WHEN** оператор меняет мастер-промпт img_pr
- **THEN** пересчитываются image_prompt кадров и всё ниже (images → anim_pr →
  videos); закадр, split, scene_design, hero остаются в кэше

### Requirement: Персистентный курсор прогресса шага

Прогресс внутри шага (какие батчи/кадры завершены) SHALL персиститься так,
чтобы рестарт процесса продолжал с курсора. Рестарт SHALL NOT откатывать
`Project.status` назад: startup_guard вместо отката помечает «running без
владельца» и передаёт решение resume-механизму.

#### Scenario: Kill -9 на 80% шага
- **WHEN** процесс убит посреди generating_images с 40/50 готовых кадров
- **THEN** после рестарта шаг продолжает с кадра 41; повторной оплаты 40
  готовых нет

#### Scenario: STOP оператора
- **WHEN** оператор жмёт STOP посреди шага
- **THEN** курсор сохранён; продолжение — с места остановки, не с нуля шага

### Requirement: Lease с TTL и владельцем

Захват единицы работы SHALL оформляться lease {owner: pid/host, expires_at};
просроченный lease перехватывается, живой — нет. Заменяет голые
`img_gen_inflight`/`video_gen_inflight` = True (`img_streams.py:20-21`,
без TTL) и in-process `_SPLIT_LOCK` (`step_global_lock.py:14-35`,
не защищает от второго процесса). Образец уже есть в их коде:
`montage_lane_claim` (`montage_coexist.py:17-59`, TTL 7200 c).

#### Scenario: Два процесса
- **WHEN** воркер поднят дважды (4 точки входа, карта §3)
- **THEN** каждый кадр генерируется ровно одним процессом; второй видит
  живой lease и пропускает

#### Scenario: Умерший владелец
- **WHEN** процесс-владелец умер, lease истёк
- **THEN** кадр перехватывается без ручного вмешательства (as-is: кадр
  «занят» до повторного входа в шаг)

## Acceptance (критерий этапа)

Убитый на 80% прогон доезжает рестартом за стоимость остатка (проверяется по
[[cost-accounting]], если этап 3 уже сделан, иначе по счётчику вызовов);
смена промпта пересчитывает ровно конус зависимостей.
