# Change: studio-run-checks

**Дата:** 2026-09-16
**Основание:** решение владельца. Бэкенд готов, кнопок в UI нет.

## Why

Две проверки существуют только как параметры API — оператор упирается
в них вслепую:

1. **dry_run («Проверить перед запуском»).** Сценарий: оператор жмет
   «Сгенерировать» на дорогом шаге (видео — $0.3–0.5/клип), а шаг не может
   стартовать: проект занят другим шагом или data-guard видит нехватку
   данных. Сейчас это выясняется фактом упавшего прогона (время, а иногда
   и деньги). `POST /steps/{code}/run?dry_run=true` уже отвечает
   `{ok, would_status, warnings}`, ничего не меняя. Кнопки нет —
   `api.runProjectStep({dryRun})` в коде есть, вызова из UI нет.
   Запрещенные шаги (`hero/items/img/video/audio/music` — там живые деньги
   Outsee/ElevenLabs) dry_run отклоняет с 400: проверка только для
   дешевых шагов (plan/script/split/enrich/...).

2. **vision-decision («Разрулить vision-паузу»).** Сценарий: GPT-проверка
   кадров не проходит N кругов — проект встает в `paused` с причиной
   `vision_rounds_exhausted`. Ловушка: **ручной перезапуск ноды счетчик
   НЕ сбрасывает** — проект висит вечно. Выход только явным решением:
   `more_rounds` (еще круги, снять паузу) или `accept_pending` (принять
   кадры как есть). Эндпоинт `POST /{id}/vision-decision` есть
   (`projects.py:568`), вызовов из фронта — ноль (`grep vision-decision
   web/src` пуст). Без кнопки пауза лечится только руками через API.

## 0. Что НЕ берем

- Логику бэкенда не меняем: оба эндпоинта работают и покрыты тестами.
- Stage-воронку не трогаем сверх строк карточек (скоуп stage — отдельно,
  отложено владельцем).
- Новых эндпоинтов нет.

## 1. Берем

### 1.1 Кнопка dry_run
- `node-studio.tsx` (панель шага, рядом с «Сгенерировать»): вторичная
  кнопка «Проверить» → `api.runProjectStep({dryRun: true})` → показать
  `would_status` + список `warnings` (тост/панель); при 400 — текст ошибки.
- `stage-card.tsx` `NodeRow`: та же проверка по ховеру (иконка), результат —
  тултип/тост. Только для шагов, не входящих в `FORBIDDEN_DRY_RUN_STEPS`
  (список отдать с бэка? нет — фронт знает те же коды; сверить с
  `studio_dry_run.py:16`).
- Состояние проекта не меняется (гарантия бэка), повторный клик безопасен.

### 1.2 Кнопки vision-decision
- Зона HITL (`hitl-banner.tsx` / карточка стадии в `waiting_hitl`):
  показывать **только** когда проект `paused` и `pause_reason.code ===
  "vision_rounds_exhausted"` (поле уже есть в API проекта).
- Две кнопки: «Ещё круги» → `POST vision-decision {action: "more_rounds"}`,
  «Принять как есть» → `{action: "accept_pending"}`; после — инвалидация
  `project/project-run`, тост с результатом.
- Вне паузы кнопок нет (не захламляем UI).

## 2. Верификация
- `tsc --noEmit`, `npm run build`, hex-гейт (без новых цветов вне токенов).
- Смоук: dry_run на `plan` (200, warnings видны) и на `img` (400);
  vision-кнопки видны только в нужной паузе (проверка на моке состояния).
- Существующие e2e/guardian — зелено. Коммит/пуш — после ручной проверки.
