## D. work_leases

- [x] D.1 Модель `WorkLease` (`app/models.py`): project_id, unit_key,
      owner, expires_at; unique(project_id, unit_key), индекс expires_at.
- [x] D.2 `app/services/work_lease.py`: `acquire(...)` одним
      INSERT…ON CONFLICT…WHERE expires_at < :now (rowcount), `release`
      в finally, `renew`, owner=host:pid:task_uuid; TTL из settings
      (default по типу единицы: img 15 мин, video 30 мин, шаг 60 мин).
      Fencing [панель 3/3, блокер]: release = DELETE WHERE owner=:me;
      renew = UPDATE WHERE owner=:me AND expires_at > :now; rowcount=0
      на renew → задача прекращает единицу и НЕ публикует результат;
      проверка владения перед записью результата. Каждая операция — в
      собственном коротком session_scope с немедленным commit и своими
      ретраями [панель 2/3] — не внутри долгой сессии шага.
- [x] D.2a Step-level lease `unit_key="step:<code>"` на входе в handler
      (захват ДО смены статуса на running, renew по ходу, release в
      finally) — БД-видимый признак живости для всех шагов; критерий E.3.
      Момент захвата per-unit lease — после gen_queue-hold/слотов, перед
      самой работой; renew-fail посреди генерации = остановка единицы
      [панель 2/3].
- [x] D.3 Замена `img_gen_inflight`/`video_gen_inflight`
      (`generate_images.py`, `generate_videos.py`, recover-пути) на lease;
      маркеры в attrs перестают писаться, legacy-маркеры игнорируются

- [x] D.4 Замена `_SPLIT_LOCK` (`step_global_lock.py`) на lease

- [x] D.5 Тесты: конкурентный захват (rowcount=1 ровно у одного), перехват

## Приёмка

Живой прогон на Chattiq: (1) kill -9 на ~80% медиа-шага → рестарт, ▶ —
доезжает за остаток (счётчик вызовов/llm_metrics), двойной генерации нет;
(2) смена мастер-промпта img_pr → пересчёт ровно конуса
images→anim_pr→videos, остальное кэш-хиты (по логам «cache hit»).
Зелёные юнит-тесты — необходимое, не достаточное. По приёмке — архив
change.

## Отклонения реализации от плана (зафиксировано по факту, 2026-08-21)

- **C.0**: step-level hash реализован для split (`meta.split_input_hash`,
  короткое замыкание `split_completed` валидно только при том же входе) и
  для всех text_job-шагов (hash внутри `text_job`). plan/script/hero/items
  собственных коротких замыканий по чекпоинту не имеют (каждый запуск —
  живой вызов) — писать им hash в NodeRun.meta нечем короткозамыкать;
  добавится при появлении их чекпоинтов.
- **C.5**: отдельный курсор батчей не вводился — resume apply_ops уже
  идёт добором по незаполненным полям (`skip_if_field`, «выход в БД =
  курсор»), что удовлетворяет правилу «применённые до падения — не
  кэш-хит целого шага»; полная инвалидация — каскад C.7. Шаги с
  `replace_frames` (split) резюмируются целиком (C.0).
- **C.6**: медиа-legacy БЕЗ hash в attrs принимается как раньше (не
  mismatch) — осознанное отступление от «legacy = mismatch»: иначе деплой
  вызвал бы массовую платную регенерацию готовых проектов. Mismatch
  детектится только при сохранённом hash. temp+rename не вводился:
  гарантию даёт порядок «hash только после принятого Artifact» + перенос
  протухших файлов в `stale/`; probe перед переиспользованием — этап 4
  (media_probe-каскад). audio per-clip hash не вводился: ASR-кэш уже по
  sha256 текста, закадр меняется только через enrich → каскад C.7.
  Провайдер/модель видео в hash v1 не входят (меняются осознанно
  оператором — пересчёт через reset).
- **D.2a**: step-lease берётся в обвязке `advance_project` (после смены
  статуса, не до) — окно «running без lease» ограничено одним тиком
  воркера и покрыто grace реконсайлера. Renew-fail step-lease в v1
  логируется (WARNING), шаг изнутри не прерывается — fencing единиц
  работы обеспечивают per-unit lease. Per-unit acquire — в задаче
  генерации после слота провайдера (как в плане).
- **D.3**: serial CDP-пути (браузерный Outsee) оставлены без per-unit
  lease — один Chrome физически исключает второй процесс; HTTP-пути
  (основные) покрыты. Shot2-claim видео сохранил legacy-маркер как
  локальную защиту волны.
- **E.1**: у running-проектов роль «ждём ▶» играет метка
  `orphaned_running` (фильтр воркера) — `arm_auto_await_manual_start`
  для running всегда был no-op; ▶ (`start_step` /
  `clear_auto_await_manual_start`) снимает метку.
- **E.3**: mass-pause батчей на старте сохранён как был (консервативно);
  дифференцированная политика «пауза только при неизвестном состоянии» —
  отложена до живого прогона с батчами.
- **Тесты**: полный прогон = 69 предсуществующих фейлов, список
  побайтово совпадает с чистым деревом (сверено дважды); тесты,
  фиксировавшие старую семантику (откат guard, линейный каскад reset,
  legacy-inflight, чекпоинты без hash), обновлены под контракт этапа 2.
