Ниже — исходные описания дыр (исторический снимок). Не читать как актуальный TODO.

### 2.1 Списание шага считает чужие строки проекта
`step_billing._spent_since` (`step_billing.py:302–315`) берёт сумму `llm_calls` +
`media_calls` по `project_id` и `id > mark` (`_ledger_mark`, `:287–299`), без фильтра
по `node_key` и без фильтра `result`. Три следствия: в шаг попадает параллельная
работа того же проекта (например, перегенерация монтажа в момент шага); попадают
строки `result="error"`; попадают нули от unpriced. Правка: считать по `ref_ids`,
собранным вокруг шага (как теперь делает `create_billing.capture_rows`), либо
добавить фильтр `node_key` и исключить `unpriced` из суммы явным решением.

### 2.2 Упавшая генерация получает полную цену
`media_call` всегда пишет строку (`media_ledger.py:337–384`), а `compute_cost`
(`:193–212`) считает её по прайсу независимо от `result`. `totals` (`:387`) и
`_spent_since` фильтра по `result` не имеют. Берёт ли провайдер деньги за упавшую
генерацию — не проверял; если не берёт, факт завышен на все error-строки. Правка:
для `result="error"` писать `cost_usd=0` + `unpriced`/пометку «цена неуспеха
неизвестна», а не полную ставку.

### 2.3 У `llm_calls` нет признака «цена неизвестна»
`LlmCall` (`models.py:999–1038`) флага `unpriced` не имеет; при отсутствии модели в
прайсе `price_for` (`llm_ledger.py:175–189`) отдаёт 0 и пишет одно WARNING. Ноль
неотличим от бесплатного вызова и от `unbilled` (обрыв без usage). Отчёт обходит это
эвристикой `cost_usd <= 0` (`admin_costs.py:197`), но сама строка журнала ложна, а
бюджет-контроль (`gpt_api.py:2651–2656`) видит ноль. Правка: колонка `unpriced`
(или `price_known`) в `llm_calls` + заполнение в `record` + миграция alembic
(`migrations/versions/`); в отчёте считать по флагу, а не по нулю.

### 2.4 «Повторить» героя не передаёт модель
`generate_hero.py:930` и `:1508` зовут `outsee.regenerate_image(out_path)` без
`model_slug`, обёртка (`outsee.py:2598–2630`) пишет `model=""` → ключ `outsee:`
не находится (`media_ledger.py:148–190`), строка `unpriced`, цена $0. Правка: брать
slug из `resolve_node_media_settings(project, node_type="hero")` (как в смете,
`quote.py:204–220`) и передавать в вызов.

### 2.5 CDP-исполнение Outsee без факта
`OutseeBot.generate_image` (`outsee.py:1935`) сначала пробует HTTP (там факт пишется,
`outsee_http.py:1638`), но при отказе API уходит в браузер — эта часть без факта.
Так же видео (`outsee.py`: CDP-ветка после `_try_http_video`). Три места, где это
достижимо:
1. `app/services/test_prompt.py:154` — прямой вызов бота, обёртки нет;
2. картинки шага: `outsee_retry.py:931–933` — при включённом HTTP обёртка доверяет
   нижнему слою, а он может свалиться в CDP;
3. видео шага: `outsee_retry.py:1494–1497` — то же самое.
Правка: обернуть публичные `OutseeBot.generate_image`/`generate_video` целиком (как
сделано для `regenerate_image`) либо писать факт в самой CDP-ветке бота.

### 2.6 Варианты сцены списываются нулём
`project_ops.py:936` оборачивает вызов в `step_billing(p, "scene_variant")`, но
`generate_scene_variants` (`montage_scene_editor.py:1082–1097`) идёт в
`gpt_client.ask_fresh` без контекста учёта: `bind_project_llm` стоит только в
`pipeline.py:176`, чат — `loop.py:489`. Строки ложатся с `project_id=NULL`,
`_spent_since` по проекту пуст → списано 0. Правка: привязывать учёт в
`generate_scene_variants` (`use_accounting(LlmAccountingContext(project_id, ""))`)
или в самом `step_billing` (тогда закроются и 2.7, и будущие ручные шаги).

### 2.7 Перегенерация монтажа: LLM-часть не привязана
`montage_board_apply_job.py:135` ставит `step_billing(project, "montage_regen")`;
медиа-строки проекта есть (project_id передаётся аргументом в
`generate_*_with_retries`), а LLM-правки промтов идут без привязки → списание ниже
факта. Тот же фикс, что 2.6.

### 2.8 `node_key="chat"` не признан служебным — закрыто в task-6
`loop.py:489` пишет `node_key="chat"`, а `cost_attribution.NON_STEP_KEYS`
(`cost_attribution.py:61`) знал только `adhoc` и пусто: в отчёте чат попадал в
корзину «вне шагов» как незнакомый ключ. В рабочем дереве `chat` уже добавлен
(`cost_attribution.py:62`). Осталось: имена вроде `montage_regen` и `scene_variant`
тоже придётся внести в `NON_STEP_KEYS`, если их начнут привязывать (2.6, 2.7).

### 2.9 `ref_table="create_generations"` — не таблица
`create_billing.py:51` пишет проводку с `ref_table="create_generations"` и
`ref_ids` из `media_calls`. Класса/таблицы с таким именем нет (`models.py`: список
классов), сверка (`admin_costs.py:331–343`) группирует заряды по этой строке как по
имени журнала. Правка: `ref_table="media_calls"` — тогда ключ сверки совпадает с
местом, куда указывают id.

### 2.10 Оценка холда Outsee не из прайса
`outsee_http.py:98–112`: видео $0.80 (sora) / $1.20, длиннее 5с — с коэффициентом;
картинки $0.03–0.12. В прайсе видео `outsee:veo-3-1-lite` — $0.45 за вызов,
картинки — $0.015–0.03. Холд завышается в разы (списание по факту вернёт лишнее, но
резерв блокирует баланс). Правка: считать оценку через `media_ledger.price_for`, как
смета шага (`quote.py:182–188`).

### 2.11 Прайс veo расходится сам с собой
UI-каталог `vibecode_catalog.py:119` показывает `veo-3-1-lite` = $0.15 за видео,
а `media_prices.json` (`outsee:veo-3-1-lite`) — `usd_per_call: 0.45`. Догадка: 0.45 —
это 6с по $0.075/с, тогда 0.15 — другой тариф или устаревшая цифра. Наугад не
правил: нужен ответ владельца, какая ставка настоящая, иначе себестоимость видео
завышена/занижена втрое.

## 4. Списание шага против факта

Механика: до шага холд по смете (`step_billing.py:144–168`), после — списание
суммой фактических строк (`:231–243`). Владелец и админ не тарифицируются вовсе
(`:118–136`); бесплатный уровень пишет подарок той же суммой (`:170–203`). Create
закрывает холд по id своих фактов (`create_billing.py:44–94`), unpriced в сумму не
входит (`:63–75`) — это соответствует контракту.

Что расходится:
1. `_spent_since` берёт всё по проекту, а не по шагу (2.1).
2. Error-строки входят в сумму с полной ценой (2.2).
3. Unpriced входят нулём — списание молча ниже факта; в лог попадает только
   `WARNING` прайса.
4. Ручные шаги вне конвейера (монтаж, варианты сцены) LLM не привязывают — списание
   ниже факта (2.6, 2.7).
5. Холд Outsee в «Генерации» считается по своей оценке, а не по прайсу (2.10) —
   на сходимость не влияет (списание по факту), но резерв не соответствует цене.

Сверка админа: `admin_costs.py:312–348` раскладывает settle-проводки по `ref_table`
и считает долю, подтверждённую ссылками на строки. Пункт 2.9 портит эту раскладку.

## 5. Привязка расхода к проекту

`node_key` → шаг: `cost_attribution.NODE_KEY_STEP` (`cost_attribution.py:28–54`),
слоты `n_excel_gpt_<n>` и веер сцен (`:56–84`); неизвестный ключ идёт в
