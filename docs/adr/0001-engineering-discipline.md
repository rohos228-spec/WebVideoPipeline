# ADR-0001: инженерная дисциплина как код

**Дата:** 2026-09-04
**Статус:** принято
**Контекст-решение владельца:** «уложить все проверки в скрипты, пайплайны
и политики, чтобы дисциплину нельзя было обойти».

## Контекст

До этого дисциплина держалась на гейте `.claude/verify.json` (сильный, но
описывает только качество кода) и на памяти владельца. Не были описаны:
определение готовности, ветки и коммиты, критерий «когда нужна спека»,
откат, хотфикс, инциденты, миграции, секреты, долг. Перенос форка
заказчика 2026-09 показал цену: 25 файлов уехали на прод без тестов на
изменённые строки, и удержать это можно было только устной договорённостью.

Панель чужих моделей (2026-09-04) нашла дыру, которую никто не видел:
`ci.yml` не запускается на `main` (`branches-ignore`), а `release.yml`
игнорирует `.claude/**`. Пересечение означало, что push в `main`,
меняющий только конфиг гейта, не проверялся вообще — то есть ослабление
самого гейта было единственным изменением без серверной проверки.

## Решение

1. Конституция (`docs/constitution.md`) — железные правила CR/AR/SR/WR,
   меняются только через ADR.
2. Политика (`docs/ENGINEERING-POLICY.md`) — процесс, у каждого правила
   указан машинный исполнитель. Правило без исполнителя не пишем.
3. Исполнители: ярус `policy` в гейте (`scripts/policy_check.py`), хук
   `commit-msg`, workflow «Политика» на каждый push без исключений по
   путям, еженедельный аудит зависимостей.
4. Обвязка: `preflight.sh`, `release.sh`, `rollback.sh`, `backup_db.sh`,
   `restore_test.sh`, журнал релизов.
5. Реестр долга `docs/DEBT.md` с базой состава исключений; сверяется
   состав, а не количество — иначе узкое исключение подменяется широким
   при том же счётчике.

## Последствия

- Прямой коммит в `main`, рост долга, контрактное изменение без спеки и
  незаархивированный change останавливают push и краснеют на сервере.
- Три завершённые спеки пришлось сразу увести в архив — правило нашло
  нарушение в первый же прогон.
- Обещание «обойти невозможно» сознательно не даётся: владелец —
  единственный админ. Даётся другое: случайно не обойти, обход оставляет
  след, агент обойти не может.
- Незакрытым остаётся то, что требует решения владельца вне репозитория:
  защита ветки `main` в настройках GitHub (обязательные проверки).

## Альтернативы

- Оставить как было: дешевле сегодня, но каждый следующий перенос кода
  заказчика снова торгуется устно.
- Полный набор церемоний (обязательный ревьюер, PR-шаблоны, релизные
  окна): для одного разработчика с агентами это ритуал без выгоды.
