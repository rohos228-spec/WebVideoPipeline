# HANDOVER — пивот video-pipeline в SaaS, состояние на 2026-08-23 (вечер)

**Ветка:** `saas-pivot` (от `hardening`). **Спека:** `docs/SAAS-PIVOT.md`,
она источник правды по решениям; этот файл — про состояние работ.

Прочитай целиком до первой правки. Половина очевидных ходов здесь уже
сделана, а несколько — уже проверены и оказались неверными.

---

## 1. Что продаём

Пользователь заходит в чат, пишет, какой ролик хочет, агент ведёт его по
шагам конвейера с визуализацией. Каждый шаг показывает цену **до** запуска,
деньги списываются с предоплаченного баланса кредитов. Самый дорогой шаг —
генерация видео — последний.

Курс: **1 кредит = $1 себестоимости, маржа ×3**. Пополнение в рублях с
конвертацией по курсу в момент пополнения, все расчёты внутри в долларах.
Бесплатно всё до первой генерации видео на аккаунте.

Себестоимость ролика 70 с (24 кадра, с озвучкой) — **$5.625**, цена
**16.88 кредита**. **82% этого — видео.** Из этой пропорции следует вся
конструкция интерфейса: итерация идёт на картинках (в 54 раза дешевле
клипа), видео покупается один раз.

### 2.1 Котировка (Этап 0, готово)

* `app/services/credits.py` — доллары ↔ микрокредиты (целые, 10⁻⁶), маржа,
  округление. Цена вверх, баланс вниз.
* `app/services/cost_attribution.py` — мост `node_key` журналов →
  `step_code` графа зависимостей. Незнакомый ключ идёт в отдельную корзину,
  а не в ноль.
* `app/services/quote.py` — смета шага: медиа точно по прайсу, текст по
  истории прогонов. `quote_cascade` берёт конус из `step_dependencies`.

Проверено на живом проекте #2: видео 13.68 кредита ровно, ролик целиком
$5.48 против $5.625 в §6.1 (разница — слоты обогащения).

### 2.2 Основание SaaS (Этап 1, **проверено на живом Postgres**)

* `app/db.py` — движок по диалекту; привязка арендатора к транзакции.
* `app/services/tenant.py` — арендатор в ContextVar, канонизация UUID,
  запрет многоарендного режима там, где RLS нет.
* `app/services/tenant_tables.py` — **один** список изолируемых таблиц.
* `app/services/db_busy.py`, `db_json.py` — различия диалектов.
* `app/services/rls_check.py` — проверка, что изоляция реально в силе;
  зовётся из lifespan и роняет старт.
* `app/services/credit_ledger.py` — холд → списание → возврат.
* `app/services/step_billing.py` — касса вокруг шага.
* `migrations/versions/0005`, `0006`.

### 2.3 Личность (Этап 2, приёмная сторона готова)

* `app/services/billing_jwt.py` — разбор и проверка токена биллинга.
* `app/web/identity.py` — ASGI-middleware: закрывает `/api/*` и `/ws/*`,
  кладёт арендатора в контекст запроса.
* `app/services/tenant_provisioning.py` — счёт при первом входе, подарок
  ровно один раз (признак ищется в леджере, не во флаге).
* `app/web/routers/me.py` — `/api/me`: личность, баланс, момент заведения.

`tenant_id` — это `User.id` биллинга, без таблицы соответствия: там
`@PrimaryGeneratedColumn("uuid")`, здесь `sa.Uuid`.

### 2.4 Касса врезана в исполнение шага

Котировка и леджер были написаны, но не соединены с конвейером: `quote.py` и
`step_billing.py` не звал никто. Врезка стоит в `advance_project_job` —
единственной точке, через которую проходит любое исполнение шага.

* Резерв до шага, списание по факту из журналов, возврат целиком при падении.
* Объём шага (кадры / символы) касса выясняет сама: `step_billing.step_volume`.
* Нехватка кредитов — не падение шага, а ожидание пополнения. Иначе счётчик
  неудач воркера откатывал бы проект назад за то, что клиент не пополнил счёт.
* Цена до нажатия: `GET /api/projects/{id}/steps/{code}/quote`, каскад — тот
  же путь с `?cascade=1`. Остаток и проводки: `GET /api/billing/balance`.

### 2.5 Бесплатный уровень

`app/services/free_tier.py` + ревизия `0008`. Бесплатно всё до первой
оплаченной генерации видео **на аккаунте**; граница по аккаунту, а не по
проекту, иначе подарок повторяется с каждым новым проектом.

Три предохранителя: видео никогда не бесплатно, потолок подаренной
себестоимости ($3 по умолчанию, проверяется по p90), число бесплатных
проектов (1). Счётчиков нет — всё производная от леджера: промо-проводки с
нулевой дельтой и фактическим `cost_usd`.

Не выполнено: подтверждение почты до первого шага. Токен биллинга не несёт
`emailVerified` — нужна правка в `auth.service.ts::sign`.

### 2.6 Изоляция за пределами базы

RLS закрывает базу и больше ничего. Две дыры, обе закрыты:

* **Файлы отдавались по пути.** `GET /api/files?path=…` проверял только, что
  путь под `data_dir`, — то есть защиту от path traversal, а не
  принадлежность. `data_dir` в SaaS общий: чужой слаг открывал чужой ролик.
  Закрыто `app/services/file_scope.py`, ответ 404 (403 подтверждал бы слаг).
* **Половина API — инструменты владельца.** `/api/fleet` запускает PowerShell
  на машинах парка, `/api/db` листает базу, `/api/text-llm` и `/api/grsai`
  ходят к провайдерам мимо кассы. Закрыто СПИСКОМ РАЗРЕШЁННОГО
  (`identity.TENANT_ALLOWED_PREFIXES`): список запрещённого означал бы, что
  каждый новый роутер открыт, пока его не вспомнят закрыть.

Добавляя роутер, спроси: он отдаёт только данные этого клиента и тратит
только его деньги? Если да — путь в список; если нет — он инструмент.

### 2.7 Агент и чат (Этап 3, серверная половина)

* `app/services/studio_agent/` — восемь инструментов §8.3 и петля разговора.
* `POST /api/chat` — SSE: событие вызова инструмента уходит клиенту в момент
  вызова, а не после того, как модель договорит.
* Панель чата в `web/` рядом с канвасом, по кнопке «Чат» в топбаре.

Три границы вокруг модели, и все три стоят в коде, а не в промте:

* **`runStep` не получает `explicit_ui_start`** — это право оператора за
  своим канвасом (снять очередь, убить чужой шаг, стартовать поверх).
  Агенту вместо него проверка достижимости по prerequisite-статусу.
* **Порог подтверждения в 1 кредит — в инструменте**, а не в интерфейсе:
  интерфейсов будет несколько, цена одна.
* **Петля конечна (8 витков)** — каждый виток платный вызов модели.

AI SDK не взят намеренно, разбор — спека §11 этап 3.1. Живой модели агент
ещё не видел: проверки идут на подменённой.

### 2.8 Объектное хранилище

`app/services/storage/` — контракт, зеркалящий `llm-gateway/.../storage.service.ts`:
изоляция префиксом ключа, жёсткая санитизация пути, presigned-ссылки, и «нет
ключей» означает «работает локальный диск», а не падение.

* `artifacts.storage_key` (ревизия 0009) — рядом с путём, а не вместо него:
  ffmpeg монтирует с диска, отобрать у него файл значит сломать монтаж.
* Публикация — после успешного шага, в одном месте, а не из 26 точек, где
  артефакты создаются.
* Ошибка публикации не роняет шаг: ролик оплачен, его надо отдать. Ключ
  остаётся пустым, отдача идёт с диска, следующий шаг попробует снова.

Отдельно: **нехватка кредитов теперь видна наружу** — событие
`credits_required` на шину и предупреждение во фронте. Без него ожидание
пополнения неотличимо от зависшего проекта, и человек идёт жаловаться вместо
того, чтобы нажать «пополнить». Событие приглушено пятью минутами: воркер
тикает каждые пять секунд, и сигнал на каждый тик перестают замечать.
* Опубликованный артефакт отдаётся перенаправлением 307 на подписанную
  ссылку — мимо приложения.

**Живого бакета код не видел.** Ключи и переключение отдачи под тестами,
подпись SigV4 и поведение провайдера — нет. Первым делом при появлении
бакета проверь `S3_FORCE_PATH_STYLE`: ошибка в нём выглядит как «бакет не
найден» на рабочем бакете.

### 2.9 Excel выключен в SaaS

Оказалось дешевле, чем считалось: шаги, ближайшие к деньгам, уже читают
сначала базу, а в книгу идут запасным путём. Значит развязка — это не
переписать 67 файлов, а перестать писать.

`XLSX_WRITE`: по умолчанию включено у владельца, выключено в SaaS. Гасится
ЗАПИСЬ, чтение остаётся — данные, заведённые в Excel до перехода, не
пропадают. Выключение стоит и на `ensure_initialized` (файла не появляется
вовсе), и на `_save` как последний рубеж: точек записи 67 файлов, закрывать
каждую значит забыть одну.

### 2.11 Канон внешности и фона

Главный герой консистентен фотографией: провайдер берёт её как
`subject_reference`. Второму фотографии не достанется — `image-01` принимает
РОВНО ОДНУ character-ссылку, — значит его сходство держит текст. Текст до
сих пор сочиняла модель заново в каждом батче: c02 из первых кадров и c02 из
последних описаны разными словами.

`app/services/img_pr_canon.py` лечит это тем же способом, каким вылечена
расстановка: канон собирается из паспорта героя ОДИН раз и вставляется во все
кадры дословно. Фон приводится к `shot01_bg` сцены так же. Вставка идёт
высоко — сразу после фона, до сюжета: у MiniMax хвост промта уходит первым, а
кадр с неверным лицом переснимают, кадр с бледной эмоцией — нет.

Пустой паспорт кода не смущает: он ничего не выдумывает и пишет в журнал,
у кого сходство не держит ничто.

**Чего это не решает** — см. §6.1: фотографии у второго героя всё равно нет,
и словами она заменяется лишь отчасти.

### 2.12 Маршрутная таблица (блокер SaaS, закрыт)

Воркер конвейера искал работу сканированием `projects` по статусу. Под RLS
такой запрос невозможен по построению: он межарендный, а политика запрещает
межарендное чтение. Воркер видел проекты владельца и ни одного клиентского —
и не падал при этом, а просто ничего не находил.

* `app/models.py::ProjectRoute` + ревизия `0007` — таблица маршрутов: номер
  проекта, арендатор, статус. Содержимого нет.
* Триггер на `projects` держит её в синхроне. Не приложение: статус меняют
  десятки мест, часть массовыми `UPDATE` мимо ORM.
* Политика `tenant_routes` **обратная обычной**: без арендатора видно всё
  (служебный режим воркера), с арендатором — только своё (клиент не
  перечислит чужие проекты).
* `app/services/work_routing.py` — единственный межарендный запрос в системе.
* `app/main.py::_run_worker_loop` — тик разбит на «кому служим» и «служим»,
  проход идёт под `tenant_scope` каждого.

## 3. Постгрес: закрыто, вот как повторить

Прошлая сессия писала Этап 1 вслепую — она была помечена веб-походом, `/run`
отрезан, podman не поднимался. Дыра закрыта: код прогнан на `postgres:16`.

```bash
podman run -d --name vp-pg -p 5432:5432 \
  -e POSTGRES_PASSWORD=vp -e POSTGRES_USER=vp -e POSTGRES_DB=vp postgres:16-alpine
.venv/bin/python -m pip install "asyncpg>=0.29,<1" "psycopg[binary]>=3.1,<4" "pyjwt>=2.9,<3"
podman exec vp-pg psql -U vp -d vp \
  -c "create role app login password 'app'" \
  -c "grant all on schema public to app"
TEST_DATABASE_URL=postgresql+asyncpg://app:app@127.0.0.1/vp \
  .venv/bin/python -m pytest tests/test_rls_postgres.py -q
```

**Роль обязательно `app`, не `vp`.** `POSTGRES_USER` образа —
суперпользователь, а RLS его не касается по определению: все тесты изоляции
прошли бы зелёными, не проверив ровно ничего.

**Контрольный опыт, который стоит повторять после правок политик.** Тот же
файл под суперпользователем обязан краснеть:

```bash
podman exec vp-pg psql -U vp -d postgres -c "create database vpsu owner vp"
TEST_DATABASE_URL=postgresql+asyncpg://vp:vp@127.0.0.1/vpsu \
  .venv/bin/python -m pytest tests/test_rls_postgres.py -q   # ждём 5 failed
```

Падает ровно шесть: проверка роли, видимость чужой строки, запись в чужого
арендатора, режим владельца, сквозной HTTP-тест и перечисление чужих
маршрутов. Если под суперпользователем всё зелено — значит изоляцию держит не
политика, и проверка ничего не значит.

Одиннадцать тестов файла зелёные под `app`, повторно (слаги уникальны в
каждом прогоне — база не требует пересоздания).

## 4. Ловушки — на них уже наступали

**`ENABLE ROW LEVEL SECURITY` не действует на владельца таблиц.** А
приложение подключается ровно владельцем. Нужен `FORCE`. Обойти RLS всё равно
может суперпользователь и роль с `BYPASSRLS`; это не лечится политикой,
только тем, под кем ходит приложение.

**Baseline создаёт схему из моделей — это касается и КОЛОНОК.** Не только
новая таблица возникает дважды (ревизия 0007), но и новое поле модели уже
есть в базе, поднятой с нуля. Ревизия обязана смотреть в
`sa.inspect(bind).get_columns(...)` перед `add_column` — иначе свежая
инсталляция падает на «колонка уже существует» (ревизия 0008).

**`set_config` не переживает `commit`.** После коммита сессия отдаёт
соединение пулу, и вместе с ним теряется всё, что на нём было выставлено.
Это не тонкость тестов, а причина, по которой привязка арендатора висит на
начале транзакции, а не на входе в сессию.

**Список рабочих статусов существует ровно в одном экземпляре** —
`node_registry.WORKER_ACTIVE_STATUSES`. В триггер 0007 он не скопирован
намеренно: вторая копия разошлась бы с первой молча, и воркер перестал бы
видеть целый класс шагов, ничего при этом не сломав.

**Арендатор доезжает не туда, где его ставили.** `SET LOCAL` в
`session_scope` не покрывает ни `deps.get_session` (16 роутеров), ни прямые
`SessionLocal()` (25 мест в шагах). Привязка перенесена на событие
`after_begin` сессии — теперь транзакция не может начаться, не сообщив, чья
она. Не возвращай её в `session_scope`.

**Слой личности снаружи CORS ломает фронт целиком.** `add_middleware`
вставляет слой в НАЧАЛО списка: добавленный последним оказывается снаружи.
Preflight `OPTIONS` заголовка `Authorization` не несёт — снаружи он получал
401 без CORS-заголовков. Порядок закреплён тестом
`test_cors_preflight_is_not_refused`.

**Снятие резерва — не проводка.** Первая версия писала `release` как
`+amount`, и остаток скакал на два резерва. Теперь запись с нулевой дельтой.

**Смета шага — сумма медийной и текстовой части, а не выбор.** У шага
«Картинки» есть и 24 PNG по прайсу, и проверка кадра зрением. Первая версия
занижала холд на треть.

**Одного прогона в истории мало, и он запросто отладочный.** При тонкой
истории показывается справка §6.1, резервируется худшее наблюдение.

**`0.19 * 24` в float — это 4.5600000000000005.** Вход `price_micro`
квантуется до шести знаков, иначе 13.69 кредита вместо 13.68.

**Три ревизии из четырёх были написаны на SQLite-only SQL.** Переведены на
`sa.inspect`; тест `test_migrations_are_free_of_sqlite_only_sql` следит.

**`pgrep -f "python3 -m app.main"` матчит собственную обёртку bash.** Ищи по
`"^/usr/bin/python3 -m app.main"`.

и сравнивай с ней, а не с нулём.

Осторожно: **прогон суиты сам пересобирает `ai-pack/`**, поэтому `git stash
pop` после него конфликтует. Файлы генерируемые — `git checkout -- ai-pack/`
перед `pop`.

## 6. Порядок работы, который я бы выбрал

1. **Сторона биллинга.** Завести бренд видеостудии в `llm-gateway`, выпускать
   токен на её домен, настроить Caddy. Блокируется вопросом о бренде (§7).
2. **Чат: свести ленту с кадрами и проверить на живой модели.** Серверная
   половина и панель есть (§2.7), но карточки показывают цену и число
   кадров, а не сами кадры; контактный лист живёт в канвасе. И ни одного
   прогона с настоящей моделью — все проверки на подменённой.
3. **Проверить хранилище на живом бакете** (§2.8) — подпись и
   `S3_FORCE_PATH_STYLE`. Полчаса работы, но нужен бакет.
4. **Развязка с Excel — переписывание оставшихся точек чтения на БД.**
   Запись в SaaS уже выключена настройкой `XLSX_WRITE` (§2.10), поэтому
   этап больше ничего не блокирует и может идти по одной точке за раз.

## 6.1 Что НЕ сделано — честный список

Отдельно от порядка работ, потому что путать «закрыл этап спеки» и «продукт
готов» дорого. Спека §6–§9 закрыта; продукт — нет.

**Качество картинки.**

* *Второй герой* — канон внешности теперь держит код (§2.11), но фотографии
  у него по-прежнему нет: провайдер берёт одну character-ссылку. Сходство
  словами слабее сходства фотографией, и на живом прогоне это не проверено.
  Настоящее лечение — либо генератор с несколькими субъектными ссылками,
  либо составной реф; и то и другое требует прогона живыми деньгами.
* *Фон* — приведён к канону сцены дословно, но канон один на сцену. Между
  сценами одного места фон по-прежнему держится только текстом.
* *Реф сцены (`shot1_reference`)* уходит в провайдера как **character**-ссылка
  — единственный канал, который у `image-01` есть. Для фона это заведомо
  слабый инструмент, и это стоит померить, прежде чем чинить.

**Интерфейс.** Фронт про SaaS не знает вовсе: нет входа (редиректа в
биллинг), нет баланса в шапке, нет цены на карточках шагов, нет плашки
бесплатного уровня. Панель чата есть, но кнопки «подтверждаю» в ней нет —
агент просит `confirm=true`, а человеку приходится написать это словами.
Лента показывает цену и число кадров, но не сами кадры.

**Чат.** Живой модели агент не видел ни разу: все 16 тестов на подменённой.
Ни одного сквозного прогона «описал ролик — получил раскадровку».

**Excel.** Запись выключена, чтение осталось: 67 файлов по-прежнему знают
про `project.xlsx`. Это больше ничего не блокирует, но и развязкой это
назвать нельзя — это отключённая запись.

**Хранилище.** Живого бакета код не видел: ключи и переключение отдачи под
тестами, подпись SigV4 и поведение провайдера — нет.

## 7. Что осталось за заказчиком

Два вопроса блокируют не код, а запуск:

1. **Номиналы пакетов пополнения** — размер и цена. Курс и маржа решены.
2. **Бренд и домен** видеостудии — от этого зависит значение `brand` в
   `User` биллинга, `STUDIO_BRAND` в студии и настройка Caddy.
3. **Разрешение видео по умолчанию.** Вся экономика спеки посчитана на клипе
   768P за $0.19, а система по умолчанию отдаёт 1080P за $0.33: ролик стоит
   26.96 кредита вместо 16.88, на 60% дороже. Либо ставить 720p, либо
   переписывать §6.1–6.2 под 1080P. Разбор — спека §6.2.1.

Не начинай интерфейс регистрации и оплаты, пока их нет: переделывать
придётся ровно то, что сделаешь.

## 8. Мелочи, которые всплывут

* **`.env.example` правится только человеком.** Guard-хук закрывает файл и по
  имени в команде, и на чтение. Добавить туда нужно блок SSO — текст в конце
  этого раздела. Коммитить: `! git add -f .env.example`.
* **Пути на диске привязаны к файлу базы.** `settings.sqlite_path.parent`
  служит каталогом для замка монтажной полосы (`montage_coexist`). На
  Postgres перестанет быть источником правды — нужен отдельный `data_dir`.
* **`ALLOW_UNISOLATED_TENANTS`** существует только для тестов механики
  кассы и личности. В SaaS его включение — дыра, а не удобство.
* **Старая форма входа обезврежена, но не удалена.** `/api/auth/login`
  отвечает 410, как только задан `BILLING_JWT_SECRET`. Файлы `auth.py` и
  `auth_sessions.py` уходят вместе с панелью флота (этап 3): сегодня пароль
  оттуда держит единственный существующий интерфейс.
* **Тариф озвучки одинаков на всех self-serve планах** ElevenLabs. Не
  оптимизируй озвучку: она 1.7% себестоимости.
* **Риск ToS принят владельцем осознанно** (§12 спеки). По ElevenLabs вопрос
  закрылся в нашу пользу. Остаётся MiniMax — 82% себестоимости.

Блок для `.env.example`:

```dotenv
# === Личность: SSO из биллинга (SaaS) ===
# Пусто — режим владельца: арендатора нет, работает локальный вход по
# WEB_AUTH_USER/WEB_AUTH_PASSWORD. Задано — режим SaaS: каждый запрос к
# /api/* обязан нести JWT биллинга, своя форма входа отвечает 410.
# Секрет ОБЩИЙ с llm-gateway/billing — это его JWT_SECRET, буква в букву.
# Для HS256 он должен быть не короче 32 байт (RFC 7518 §3.2).
BILLING_JWT_SECRET=
# Бренд этой студии. Биллинг мультибрендовый: уникальность пользователя —
# по паре (email, brand), поэтому токен чужого бренда подписан верно и всё
# равно не наш. Пусто — бренд не сверяется (только для отладки).
STUDIO_BRAND=
# Запас на расхождение часов между биллингом и студией, секунды.
BILLING_JWT_LEEWAY_SEC=30
# Сколько кредитов класть на счёт при первом входе. Ноль — верно: бесплатный
# уровень сделан промо-проводками, а не деньгами на балансе.
TENANT_START_CREDITS=0

# === Бесплатный уровень ===
# Бесплатно всё до первой ОПЛАЧЕННОЙ генерации видео на аккаунте.
FREE_TIER_ENABLED=1
# Потолок подаренной СЕБЕСТОИМОСТИ на аккаунт, доллары. Проверяется по p90:
# платформа платит за худший исход, а не за средний. 0 — без потолка.
FREE_TIER_SPEND_CAP_USD=3.0
# Сколько проектов можно вести бесплатно.
FREE_TIER_MAX_PROJECTS=1

# === Объектное хранилище (S3-совместимое: Cloudflare R2 и прочие) ===
# Пусто — локальный диск узла (режим владельца). «Настроено» выводится из
# наличия ключей, а не из флага: флаг разошёлся бы и уронил бы первый кадр.
S3_ENDPOINT=
S3_REGION=auto
S3_ACCESS_KEY=
S3_SECRET_KEY=
S3_BUCKET=
# Провайдеры без wildcard-DNS на поддомены бакета требуют path-style; R2
# работает virtual-hosted. Ошибка выглядит как «бакет не найден» на рабочем
# бакете — проверять этот флаг первым.
S3_FORCE_PATH_STYLE=0

# === Excel ===
# Пусто — включено у владельца, выключено в SaaS. Гасится ЗАПИСЬ книги;
# чтение остаётся, чтобы данные, заведённые в Excel до перехода, не пропали.
XLSX_WRITE=
```
