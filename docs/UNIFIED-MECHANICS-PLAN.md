# Объединение механик v1/v2 — план, решения, ход работ

> **Назначение:** единый источник правды по проекту унификации. Продолжить
> работу по нему может любой агент (OpenCode / Antigravity) после обрыва
> связи. Обновляется после каждого шага.
> **Статус (2026-10-12): код всех фаз готов и запушен в `feat/unified`.
> Идёт ручное тестирование владельцем через STUDIO.cmd. Осталось: smoke
> обеих механик, прод-аудит БД, данные по ценам, финальные решения по
> PR/домену.
> **Правило репозитория в силе:** никаких прямых мерджей `main` ↔
> `second-mechanic`. Единая санкционированная точка слияния — ветка
> `feat/unified`.

## 1. Замороженные решения владельца

| # | Решение |
|---|---------|
| R1 | Строгая изоляция: проект создаётся в одной механике и живёт в ней всегда. Проекты v1 не видны в v2-режиме и наоборот. Конвертации/скрещивания нет (перенос v1→v2 — только как будущая отдельная фича). |
| R2 | Режим хранится отдельной колонкой `projects.pipeline_mode` + индекс (не только meta). |
| R3 | Сначала аудит (выполнен, §3), потом код. |
| R4 | Данные v2 переносятся позже (фаза 5). Домен v2 — будущий staging-слот, НЕ автофейловер (оба домена на одном VPS; автофейловер stateful-приложения даст split-brain). |
| R5 | Дефолт новых проектов — `v1`, выбор механики при создании обязателен. |
| R6 | Биллинг: логику портируем как есть, прайсинг не финализируем (ждут данных владельца). Новые v2-операции обязаны идти через `step_billing`/котировки, `TODO(reprice)`. |
| R7 | PR после каждого шага с base = unified-ветка (НЕ main). main не трогаем до финала. Тесты: релевантные сьюты после шага + полный прогон и smoke в конце фазы. |

   только свои пути (`git add <пути>`): в дереве бродит EOL-шум `prompts/`
   и сайд-эффекты тестов (`ai-pack/MANIFEST.txt`, `.file_meta.json`) —
   их не коммитить, перед коммитом сбрасывать (`git checkout -- <путь>`).
4. PowerShell `>` пишет файлы в UTF-16 и ломает их — вывод git в файлы
   только байтово через python (`subprocess` + `open(...,'wb')`), с проверкой
   `git hash-object` vs `git rev-parse <rev>:<path>`.
5. Инструменты гнать из `.venv` (см. §5 выше); кириллицу в `Select-String`
   по выводу git не искать — только ASCII-паттерны.
6. Открытые вопросы (не брать без владельца): полный автомат версий
   STUDIO_VERSION (отклонён), серверная заливка data-кадров для kie
   (вариант А, см. DEFERRED в §4), репрайсинг по данным владельца,
   гигиена сьюта (48 предсуществующих падений + запись тестов в репозиторий).
