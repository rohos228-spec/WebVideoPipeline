# HANDOVER — почему многокадровые сцены выродились в портретную галерею

**Дата:** 2026-08-23. **Ветка:** `hardening`. **Проект прогона:** `#2`,
slug `nochnoy-obmen-v-poslednem-vagone`, статус `animation_prompts_ready`,
24 кадра 720×1280 на диске.

Читай целиком до первой правки: половина очевидных гипотез здесь уже
проверена и отвергнута по данным.

---

## 1. Что просит заказчик

Сцены должны быть **группами кадров в разрешённых последовательностях**, а не
слайдшоу «один кадр на ячейку закадра». Два барьера, которые он называет
нерешёнными:

1. **смена планов при сохранении позиции актёров** — общий → средний → крупный
   внутри сцены, и герой не прыгает с левой половины кадра в правую;
2. **логика перемещения предметов** — предмет не телепортируется, не исчезает
   и не появляется заново.

## 2. Что уже сделано (не переделывай)

**Слой непрерывности** — `app/services/scene_design/continuity.py` +
`continuity_apply.py`, 12 тестов. Считает кодом, а не просит у модели:

* ось действия ролика (кто слева, кто справа) — одна на всю пару за весь
  ролик, не пересчитывается в каждой сцене;
* `сторона` шота `A` / `B` / `нейтраль`; молчание = сторона сцены; перелёт
  легален только через нейтральный кадр, иначе откат и запись нарушения;
* реестр предметов: состояние переносится вперёд само, владелец вытаскивается
  из прозы в падежах («переходит к женщине» → `c02`), ловится телепорт,
  воскрешение после ухода, владелец вне кадра;
* результат — готовая фраза в `Frame.attrs["continuity"]`, например:
  `Непрерывность. Расстановка: Игнат в левой половине кадра, смотрит вправо;
  женщина в сером пальто в правой половине кадра, смотрит влево. жёлтый
  конверт держит Игнат.`

**Инструмент измерения** — `python3 scripts/continuity_report.py 2`. Считает
тем же кодом, что и пайплайн. Показывает раскадровку по сценам, ось, строку
непрерывности на каждом кадре и нарушения реестра.

**Контракты** — в `sd_camera_chrono_dyn.md` добавлено поле `сторона`
(модель приняла с первого раза: `нейтраль`×20, `A`×12, ни одного случайного
перелёта), в `sd_skeleton.md` — `у_кого` / `где` у предметов и запрет ронять
предмет из карточек, пока он в кадре.

**Одиннадцать исправленных дефектов пайплайна** — см. §6.

## 3. Диагноз: где именно сломалось

### 3.1 Главное — непрерывность не доехала до промта картинки

Данные на кадрах есть, в промт попали один раз из двадцати четырёх:

```
кадров с attrs["continuity"]:          23 / 24
промтов, где геометрия дожила:          1 / 24
```

Причина: **поле приехало в контекст, но агенту не сказали его использовать.**

```bash
grep -rniE "continuity|непрерывн|расстановк" \
  prompts/05_image_prompts/default.md app/services/img_pr_batches.py
# пусто
```

`db_frames.json` содержит `continuity` (whitelist в `db_frames_context.py`
починен), но мастер-промт диктует модели жёсткий состав тела промта —
«сцена на русском (Референс?/Фон/Действие/Свет/Акцент/Смысл/План-ракурс/
Эмоция/Детали/Место)». Незнакомого поля в списке нет, и модель его молча
пропускает.

**Это не компрессор MiniMax.** Гипотезу «геометрию срезало сжатие под лимит
1470» проверял: в исходных промтах (2000–3400 знаков, до всякого сжатия)
геометрии уже нет.

**Что делать:** внести непрерывность в контракт `img_pr` как **обязательную
секцию тела промта**, а не как справку. Предложение: отдельная строка
`Расстановка:` сразу после `Фон:` (то есть ДО `Действие:`), с прямым запретом
её переписывать и с требованием повторить дословно то, что пришло в поле
`continuity`. Учти лимит: MiniMax режет промт картинки по 1500 знаков
(`outsee_retry`), и компрессор выбрасывает хвост — значит геометрия обязана
стоять в начале, а не в конце.

### 3.2 Портретная галерея — решение агентов, не сбой картинок

Из 24 кадров двое в кадре только на **12, 13, 17**. Кадры 1–11 односубъектные
по данным, а не по вине `image-01`. Смотри срез камеры:

```
data/videos/nochnoy-obmen-v-poslednem-vagone/scene_design/camera.json
шотов: 32 | субъектов в шоте: {1: 26, 2: 4, 0: 2}
крупности: средний крупный 8, средний план 7, деталь 5, крупный 5, …
движение:  static 10, push-in 8, pan 6, tilt 4, handheld 3, pull-out 1
```

Крупности и движение разнообразны — то есть `sd_camera_chrono_dyn.md`
работает. Ломается другое: **26 из 32 шотов про одного человека**, хотя
сцена — диалог двоих в замкнутом вагоне. Агент `action` нарезал фазы вокруг
одного субъекта, камера честно обслужила фазы 1:1.

**Что делать:** искать не в промте картинок, а в `sd_action_chrono_dyn.md`
и `sd_camera_chrono_dyn.md`. Гипотеза для проверки: в контракте фазы есть
`subject` (один cNN), и это подталкивает к односубъектным фазам; поля «кто
ещё в кадре» нет. Плюс в camera нет требования «в сцене с двумя людьми
минимум N% шотов должны показывать обоих» — а именно оно даёт зрителю
геометрию, из которой потом читается смена планов.

### 3.3 Прямой брак кадров

* **кадр 9** — `image_prompt == '...'` (три точки, 3 символа) и это **прошло
  валидацию контракта**. Отсюда мусорная картинка. Ищи минимальную длину
  промта в `app/contracts/` / `img_pr_batches.py` — её там нет.
* **кадр 18** — промт про потолочный плафон: `shot01_action` =
  «смотрю на лампы — на лампы». Это моя бит-производная фаза из
  `repair_action_phases_from_bits`; дедупликация «глагол == хвост» добавлена
  уже после этого прогона, в новом прогоне такого быть не должно —
  но проверь.
* **кадры 11, 15** — чужие лица / посторонний персонаж. Скорее всего
  следствие §3.1: без расстановки и при `refs=1` модель достраивает людей
  сама. Перепроверить после починки контракта, отдельно чинить рано.

## 4. Как воспроизвести дёшево

Полный прогон с нуля — ~$2 и ~3 часа. Не нужен. Быстрый цикл:

```bash
# 1. поднять бэкенд (обязательные переменные — иначе шаги упадут, см. §5)
export TELEGRAM_ENABLED=false TEXT_LLM_PROVIDER=minimax \
       IMAGE_PROVIDER=minimax VIDEO_PROVIDER=minimax \
       SCENE_DESIGN_AGENT_ATTEMPT_TIMEOUT_S=900 HITL_AUTO_APPROVE=1
python3 -m app.main

# 2. посмотреть, что стоит на кадрах сейчас
python3 scripts/continuity_report.py 2

# 3. пересчитать только непрерывность (без GPT, мгновенно)
python3 - <<'PY'
import asyncio
from app.db import session_scope
from app.models import Project
from app.services.scene_design.continuity_apply import apply_continuity
async def m():
    async with session_scope() as s:
        p = await s.get(Project, 2)
        print(await apply_continuity(s, p)); await s.commit()
asyncio.run(m())
PY

# 4. перегенерить только промты картинок (~4 мин, ~$0.05) и кадры (~15 мин, ~$0.09)
curl -X POST "127.0.0.1:8765/api/projects/2/steps/img_pr/reset"
curl -X POST "127.0.0.1:8765/api/projects/2/steps/img_pr/run?node_key=n_image_prompts"
curl -X POST "127.0.0.1:8765/api/projects/2/steps/img/run?node_key=n_images"
```

Проверка результата — доля промтов с геометрией:

```bash
python3 - <<'PY'
import asyncio
from sqlalchemy import select
from app.db import session_scope
from app.models import Frame
async def m():
    async with session_scope() as s:
        rows = (await s.execute(select(Frame).where(Frame.project_id == 2))).scalars().all()
        hit = sum(1 for f in rows if "половине кадра" in (f.image_prompt or ""))
        print(f"геометрия в промтах: {hit}/{len(rows)}")
asyncio.run(m())
PY
```

Сейчас это `1/24`. Цель — близко к числу кадров, где вообще есть люди.

## 5. Ловушки — на них уже наступали, не повторяй

* **Шаг `hero` нельзя перезапускать явно.** `reset_step._wipe_hero` сносит
  ВСЕХ готовых героев и обнуляет одобрения. Каст собирается только так:
  `HITL_AUTO_APPROVE=1` → шаг сам берёт следующую пару. Я потерял двух героев
  дважды, это ~20 минут каждый раз.
* **`img/reset` стирает промты картинок**, не только PNG. Хочешь перерисовать
  кадры со старыми промтами — удаляй файлы, а не сбрасывай шаг.
* **Веер scene_design не входит в дефолтный граф** (`default_graph.py:21`).
  Без него пайплайн физически делает слайдшоу. Группа
  `scene_design_fanout_chrono_dyn` добавляется через
  `POST /api/projects/{id}/canvas/groups/{group_id}` с `{"after":"n_split"}`.
* **`pgrep -f 'app[.]main'` в одной команде с `python3 -m app.main`** убивает
  собственную оболочку: паттерн совпадает с командной строкой самого bash.
  Держи рестарт в отдельном `.sh`-файле.
* **Проект из API получает `aspect_ratio=None`** → фолбэк 16:9 в вертикальном
  пайплайне. Выставляй `9_16` явно при создании.
* **Тесты:** 6 падений в `test_scene_design_agent_chunks.py` и
  `test_scene_design_cells.py` существовали ДО этой работы, проверено через
  `git stash`. Не чини их как свою регрессию.

## 7. Порядок работы, который я бы выбрал

1. §3.1 — внести расстановку в контракт `img_pr` первой секцией после фона.
   Дёшево, проверяется за 20 минут, даёт наибольший эффект.
2. §3.3 — минимальная длина промта в валидации (кадр 9 не должен проходить).
3. §3.2 — требование в `sd_camera_chrono_dyn.md`: в сцене, где по данным двое,
   доля шотов с обоими в кадре не ниже порога. Это то, из чего зритель
   вообще читает «смена планов при сохранении позиции».
4. Перегон img_pr + img, замер доли геометрии, глазами по контактному листу.

Контактный лист прошлого прогона собирается так:

```bash
python3 - <<'PY'
from PIL import Image
import glob
ps = sorted(glob.glob('data/videos/nochnoy-obmen-v-poslednem-vagone/scenes/*.png'))
cols, rows, tw = 6, 4, 200
th = int(tw * 1280 / 720)
sheet = Image.new('RGB', (cols * tw, rows * th), 'black')
for i, p in enumerate(ps[:24]):
    sheet.paste(Image.open(p).convert('RGB').resize((tw, th)), ((i % cols) * tw, (i // cols) * th))
sheet.save('/tmp/contact_sheet.png')
PY
```
