# Эвалы и голденсеты промтов

Две разные вещи, и путать их дорого.

| | голденсет | эвал |
| --- | --- | --- |
| Что меряет | **наш код**: разбор ответа, контракт, нормализация | **модель**: годится ли ответ по существу |
| Сеть | нет | да, живые вызовы |
| Стоимость | ноль | деньги за каждый прогон |
| Детерминизм | полный | нет, ответ каждый раз другой |
| Где живёт | `evals/golden/`, гейт `tests/test_prompt_goldens.py` | `evals/suites/`, раннер `scripts/eval_prompts.py` |
| В гейте push | **да** | нет — по требованию и ночью |

Голденсет отвечает на вопрос «не сломали ли мы разбор». Эвал — на вопрос
«не стал ли промт хуже». Первый обязан быть зелёным всегда; второй не может
быть зелёным по определению, у него есть только оценка и её динамика.

---

## Голденсеты

### Откуда берутся случаи

Не из головы. Написанный вручную «пример ответа модели» проверяет наши
представления о модели, а реальность выглядит иначе: лишний ключ, `null`
вместо строки, число строкой, markdown-забор вокруг JSON, обрезанный хвост.

Источник — запись живого прогона:

```bash
LLM_RECORD_DIR=/tmp/vp-record python3 -m app.main    # прогнать конвейер
python3 scripts/goldens.py list /tmp/vp-record        # что записалось
python3 scripts/goldens.py add /tmp/vp-record/vp_sd_skeleton__20260825-101500__ab12cd34ef.json \
    --name лишний-ключ --note "модель добавила phase_index"
```

`add` считает ожидание САМ, прогоняя ответ через контракт. Не проходит —
случай записывается как ожидаемый отказ; это тоже голден, и часто более
ценный: он фиксирует, что именно модель делает не так.

### Когда голден краснеет

Либо сломали разбор — чинить код. Либо контракт изменён осознанно — тогда:

```bash
python3 scripts/goldens.py bless evals/golden/vp_sd_skeleton/live-2026-08-23.json --yes
```

`bless` печатает, что именно поменялось, и без `--yes` ничего не делает:
молча обновлённый голден — это голден, который перестал что-либо держать.

### Что в корпусе сейчас

```bash
python3 scripts/goldens.py show
```

Стартовый корпус собран из артефактов живого прогона 2026-08-23: пять срезов
`scene_design` (проходят) и два реальных отказа `vp_apply_ops`, где модель
вернула `phase_index`, `beat` и `переход` вместо канонических имён.

Контракты без единого случая перечисляет тот же `show`. Гейт на это НЕ
краснеет: собрать корпус на все двенадцать контрактов разом нельзя — нужен
прогон, дошедший до каждого шага. Список пробелов — рабочий план.

## Эвалы

### Как устроен набор

`evals/suites/<имя>.json` — вход промта, критерии и порог:

```json
{
  "name": "план ролика",
  "step_code": "plan",
  "cases": [
    {
      "id": "метро-ночь",
      "vars": {"topic": "Ночной обмен в последнем вагоне метро"},
      "criteria": [
        {"kind": "contract", "contract": "vp_frame_split"},
        {"kind": "min_items", "path": "frames", "value": 20},
        {"kind": "no_placeholder"},
        {"kind": "judge", "ask": "Есть ли в плане конфликт и его разрешение?"}
      ]
    }
  ],
  "threshold": 0.8
}
```

Критерии считаются по возрастанию цены: сперва бесплатные детерминированные
(контракт, счётчики, запреты), и лишь если они прошли — судья-модель. Судья
дорог, и спрашивать его про ответ, который не прошёл схему, незачем.

### Прогон

```bash
python3 scripts/eval_prompts.py --suite evals/suites/plan.json          # один набор
python3 scripts/eval_prompts.py --all --out evals/reports/2026-08-25.json
python3 scripts/eval_prompts.py --all --dry-run                          # без сети: что бы гонялось
```

Отчёт — оценка на набор и на случай, с текстом каждого проваленного критерия.

### Храповик оценки

`evals/baseline.json` хранит последнюю оценку каждого набора.
`--ratchet` роняет прогон, если оценка просела больше чем на `--tolerance`
(по умолчанию 0.05): модели плавают, и требовать точного совпадения значит
получить красный прогон на ровном месте. Рост базы подтягивается сам и
просит закоммитить — сужение должно быть видно в диффе.

**Эвалы не стоят в push-гейте.** Они ходят в сеть и тратят деньги; гейт,
который стоит рубль за нажатие, обходят. Их место — ночной прогон и правка
промта: поменял промт — прогони его набор до и после.
