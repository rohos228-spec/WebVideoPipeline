# План работ: стабилизация video-pipeline

Заказчик: владелец репо (rohos228-spec). Исполнитель: внешний контрактор.
Основание — аудит `../job/data/video_pipeline_audit.md` (4 прохода по коду).
Оплата: проектно, по этапам, 50% на старте этапа / 50% по критерию приёмки.

Стек заказчика: FastAPI + SQLAlchemy 2.0 + SQLite, Pydantic v2 (в deps, на
LLM-путях НЕ используется), httpx → OpenAI-совместимые релеи (kie/vibecode),
Next.js 15 студия. Оркестратор — самописный (poll `Project.status` + if/elif).
LangGraph/Temporal НЕТ и вводить их не планируется — вся работа ложится в
существующий стек.

## Принципы
- Ничего не переписывать целиком. Врезаемся в существующие точки: `gpt_api.chat()`,
  `NodeRun`, `db_apply`, `vision_check_loop`. Ценность — починка фундамента ИХ
  конструкции, не миграция на фреймворк.
- SDD: каждый этап — openspec-change (proposal → tasks → delta), архивируется по
  приёмке. Спекуются только затрагиваемые capability, не весь репо.
- Каждый этап приёмится на ЖИВОМ прогоне, не на юнит-тестах (их harness-гейт
  выключен autouse-фикстурой — зелёному CI доверять нельзя).

## Порядок этапов (важен — есть зависимости)
Контракты (этап 5) идут ДО кэша (этап 2): кэш по хэшу входа требует, чтобы «вход»
был определён, а его определяет реестр контрактов. Langfuse (3) — в любой момент.
Фактический порядок исполнения: 1 → 5 → 2 → 4 → 3.

## Роадмап (после, не в текущей смете — допродажи с обоснованием из кода)
- Голден-сет тестов на ноду (~$300-400) — после стабилизации контрактов.
- RAG «память завода»: канон стиля/персонажей + few-shot из удачных сцен по скорам
  (~$500-700) — «самообучение» из вакансии; невозможно до этапов 3-5 (нечего
  ретривить). Лекарство от «STYLE-lock выключен» + потолка 2 референса на кадр.
- Prompt caching релеев (мастер-промпты 40-130 КБ на каждой пачке) — минус десятки %
  input-токенов; продать цифрой после того, как этап 3 покажет косты.
- Лимитеры per-провайдер + circuit breaker (429 не отличается от 500, Retry-After
  не читается).
- Межпроцессный lock (воркер из 3 точек, лизинг без TTL).
- xlsx-слой как второй SoT (61 модуль, магические номера строк) — трогать последним.
- check_analysis.py (1587 строк, 52 регулярки) — переработка парсинга вердиктов.
